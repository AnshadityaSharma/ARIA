### Coordinator contract to design before implementation

A compound request must parse into an explicit, bounded set of typed `Action` nodes and dependency edges. Control words and quoted literal payloads remain distinct; ambiguous joins abstain. A node carries immutable parameters and target expression; verified predecessor output, not a global `WindowState` last-action pointer, binds references such as “Camera” or “it” to one exact window identity. The coordinator has no executor or risk authority. It submits each ready node through the Engine kernel, including validation, deterministic policy, confirmation, target recheck, execution and verification. A pending confirmation pauses only its dependent branch unless shared state or conflict requires wider pause; a new activation/cancel invalidates pending work safely. Conflicting actions on one window or browser page serialize. Independent launches can overlap only after refactoring the present single Engine lock/worker boundary without weakening policy or sharing a mutable before-window snapshot; application registration and returned window must be uniquely correlated per launch. No branch consumes an unverified predecessor. Outcomes are per-node verified/failed/cancelled/unknown; aggregate success requires every required node to be verified. A timeout or partial failure cancels dependents, reports completed work, and never retries a non-idempotent action without fresh observation and user intent.

### Native input decision gate

“Click” at the user's physical cursor means sampling current Windows pointer coordinates and the foreground/window identity at the defined execution boundary. It does not authorize image recognition or a guessed UI control. A confirmation dialog can move focus or pointer, so recheck both after confirmation or decline. A click can submit, purchase, or delete; the policy must not classify an unknown underlying control as harmless merely because the input event is small. For typing/key chords, bind the exact foreground target and input payload, preserve literal text, reject secure/elevated or changed targets where Windows prevents reliable control, and report OS input delivery separately from observed application effect. Define a narrow allowlist of verifiable low-consequence cases or require explicit confirmation; if a safe risk/verification rule is not practical, defer the capability. Do not add vision to solve this gate.

### Shard and compact transcript-panel design brief

Phase 8 compares several original Shard silhouettes and panel layouts at its existing design gate; “Dynamic Island” describes compact expansion, not a shape or animation to copy. Candidate states are idle/minimal, wake, listening without words, speech/partial revision, final transcript, executing with per-action progress, confirmation, verified success, and error/partial failure. The panel should expand only as much as needed, clamp long text to a bounded multi-line area with accessible full text, and return to minimal/hidden after a measured dwell. Motion is restrained, cancelable, and fully understandable with reduced motion; any audio-reactive cue must use existing capture state or inexpensive metering, never a second audio stream. No continuous screenshot or blur renderer is justified.

Prototype first with the existing Tk event queue and Windows no-activate behavior; switch toolkit only if the comparative performance/accessibility gate demonstrates a need. Coalesce versioned transcript events on the UI thread, discard stale revisions, and preserve final/error priority. Use monitor work area and DPI-aware positioning with explicit full-screen and taskbar behavior. Idle click-through is a candidate only if it cannot hide confirmation or block normal input; active confirmation remains keyboard/screen-reader usable. Review light/dark/high-contrast, scaling, multiple monitors, focus, occlusion and long text. The panel displays backend facts and never synthesizes words, grants permission, or substitutes success for an unverified result. If renderer creation/update fails, the controller still follows the safety kernel and exposes an error through the available non-visual path. Compare first frame, update cadence, command-path impact, idle/active CPU/RAM, process count and sustained idle against the existing Phase 8 budgets.
