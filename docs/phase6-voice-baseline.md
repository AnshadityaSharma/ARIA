# Phase 6 unchanged-voice baseline — 2026-10-10

`context.md` defines the Phase 6 gate. This baseline freezes observation before any capture, endpoint, ASR, confidence, normalization, or interpretation change. **The representative human-speech baseline is pending.** No consented human audio was available in the repository or provided for this task. No microphone was opened and no person was recorded.

## Current data flow and configuration

`DesktopApp`/hotkey calls `ActivationController`, which admits one worker. `VoiceController.prepare` calls `Microphone.capture`: `sounddevice.InputStream` at 16 kHz, mono float32, 50 ms blocks, fixed RMS speech threshold `.012`, `.7` s post-speech silence, and 7 s maximum. Overflow fails. Capture returns an in-memory NumPy array; default operation does not save it. `LocalASR` keeps one local `faster-whisper` multilingual `base` model on CPU `int8` with `local_files_only=True`. Its call uses `beam_size=1`, `best_of=1`, `vad_filter=True` with 300 ms minimum silence, and `condition_on_previous_text=False`. It fully consumes segments and returns one final text, language, language probability, and a derived confidence. Empty text or confidence below `.35` is rejected. `VoiceController` forwards the final text to `Engine.interpret`/the deterministic parser; `ActivationController` then sends the typed action through `Engine.execute` and its policy/verification boundary. No partial transcript is emitted. The interpreter's old experimental model is not used by default.

`Timeline` can mark microphone request/ready, capture end, ASR start/final, parse, policy, action, and confirmation events. The old `scripts/voice_benchmark.py` measures one audio file's model load, ASR, CPU, and RSS. The prior desktop benchmark used Windows-synthesized speech plus a separate microphone startup smoke. Neither supplies representative human WER or a live false-activation denominator.

## Corpus collection contract

Use a **local, opt-in** consent workflow. Explain the commands, purpose, retention period, and who can inspect audio/transcripts before recording. Keep consent records, raw WAV files, and manifests outside the repository and cloud sync, with access limited to the evaluators. Use pseudonymous speaker IDs; exclude personal names, real private paths, and sensitive spoken content. Delete recordings on the agreed schedule. The evaluator never records audio by default: `scripts/phase6_voice_baseline.py` only reads files named in an explicit manifest and never executes an action. Reports omit reference and observed transcript text by default. Inspect a discrepancy locally with the consented clip; do not paste private transcripts into issues or committed logs.

Target collection before proposing optimizations: 18 consenting speakers, six each for English, Indian English, and Hinglish, with four per cohort in development and two in held-out evaluation. Aim for 20 intended prompts and 10 negative triggered windows per speaker (360 intended and 180 negative trials), with different phrasing families and speakers across splits. This is a **collection target, not an existing dataset or statistical guarantee**. Distribute prompts across dynamically named and ambiguous applications; disposable filenames and paths; numbers, percentages, window positions, and unsupported key combinations; supported simple actions; compound attempts that should currently abstain; and unrelated speech/silence. Vary accent, speaking rate, pauses, quiet/noisy rooms, and built-in/headset microphones. Record actual microphone, distance, OS, hardware, acoustic condition, speaking rate, and exact intended outcome per trial. Review annotations with a second person before freezing each split. Do not include a native keyboard action as supported merely because a prompt asks for one. The versioned collection, annotation, exclusion, and split-freeze procedure is in [phase6-corpus-protocol.md](phase6-corpus-protocol.md).

For live capture/endpointing evidence, conduct separate explicitly consented sessions. The evaluation-only `VoiceController.prepare()` runner manually triggers 20 intended trials and at least 10 negative windows per speaker where practical, without executing an action. **Negative-triggered command proposal rate** uses all negative manually triggered windows as its denominator; it is not ambient or real-hotkey false activation. **Missed complete-command rate** uses intended trials whose expected outcome is an action as its denominator, including capture/endpoint and ASR failures. Real hotkey/UI delivery and speech-to-verified-result require separate controlled evidence. Do not run consequential commands against the real machine for corpus collection.

## Manifest and replay method

Each JSON manifest has `version: 1`, `source: human` or `synthetic`, `split: development`, `held_out`, or synthetic-only `smoke`, and a nonempty `cases` array. Each case requires `id`, `family`, pseudonymous `speaker_id`, `cohort`, `condition`, `microphone`, `speaking_rate`, nonempty `tags`, `audio_path`, `audio_sha256`, `reference_text`, `expected`, and `consent_record`. `expected` is `{ "outcome": "clarify" }`, `{ "outcome": "abstain" }`, or `{ "outcome": "action", "action": "OPEN_APPLICATION", "target": "Camera", "params": {} }` using a real typed action and its raw parser target. Empty `reference_text` is allowed for a no-speech negative; an expected action requires audible reference words. The human manifest, audio, and consent record must exist outside the repository; the audio hash must match. Development/held-out files cannot reuse speaker IDs or phrasing families. Human manifest contents contain transcripts and must be protected even though reports do not.

Run with the current virtual environment after local model provisioning:

```powershell
.venv\Scripts\python.exe scripts\phase6_voice_baseline.py --manifest C:\private\aria-voice\development.json --manifest C:\private\aria-voice\held-out.json --output C:\private\aria-voice\replay-report.json
```

The runner decodes each file to 16 kHz mono through the installed decoder, calls the unchanged `LocalASR`, applies the existing `.35` confidence gate, then asks the unchanged deterministic interpreter for an **action proposal only**. It does not use `Microphone`, resolve live targets, authorize, execute, or verify an action. The expected target is the raw parser target, so semantic target resolution requires a separate controlled evaluation. Reference text is also interpreted to distinguish interpreter/annotation misses from errors that appear only after ASR. The label `asr_or_recorded_audio` does not prove which of those two caused a mismatch. Every saved report is created without overwrite. Human reports additionally require an existing private output directory outside the repository and print only saved status and split counts to the terminal. Overall `summaries` and `cohort_summaries` are each nested by source and split; development and held-out metrics are never pooled.

WER uses Unicode word tokens (`\w+`) after case folding and aggregates edit distance over reference token count. Report it by cohort where meaningful; spelling, Hinglish romanization, filenames, and paths need separately reviewed exact-command outcomes. A zero-token reference contributes neither WER errors nor denominator; hallucinated words in such clips are assessed through proposal outcomes. Capability accuracy uses expected action clips; target/argument accuracy conditions on correct capability; false action uses all clips and negative clips separately. File-replay missed-action rate counts non-action proposals among expected action clips and excludes live microphone failures. A metric with zero denominator is `null`. p50 requires at least 10 samples and p95 at least 20; smaller runs retain per-case timings without presenting unstable percentiles. First-clip ASR timing and model-load timing are separate; later clips are warm only with the model resident. CPU is process user+system time across model load and replay; RSS is sampled after load and after all cases, not peak. No long-idle or battery claim follows from those samples.
